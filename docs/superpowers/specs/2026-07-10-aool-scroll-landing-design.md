# Лендинг АУЛ со скролл-пролётом — Design Spec
- **Дата:** 2026-07-10
  
- **Проект:** aool.space (посёлок АУЛ, Уфа / Акбердино)
  
- **Статус:** утверждён к планированию
  
## 1. Цель
Новый главный лендинг посёлка АУЛ с hero-секцией в стиле scroll-world (oso95/scroll-world): непрерывный «пролёт сквозь мир» по скроллу, как на продуктовых страницах Apple / сайте Emons. Ниже сгиба — обычные секции контента (дома, благоустройство, «почему АУЛ», манифест, CTA).

Заменяет текущий лендинг (сейчас на 1С-Битрикс). Новый — отдельное Next.js-приложение.
## 2. Ключевые решения
| Вопрос | Решение |
| --- | --- |
| Генератор видео-пролётов | **Sora-2 через Azure AI Foundry** (не Higgsfield) |
| Still-постеры сцен | Image-модель Azure (GPT-Image) или кадр из клипа |
| Движок скролла | Порт `scroll-world/references/scrub-engine.js` |
| Подход к пролёту | **A — video-scrub** с фолбэком на image-sequence (B) |
| Стек | Next.js (App Router), SSR/SEO |
| Сценарий | «Путь в дом»: снаружи внутрь, 6 сцен |
| Бесшовность стыков | connector-клипы + seam **crossfade** (встроен в движок) |

Higgsfield **не** обязателен: движок генератор-агностичен, ему нужны на сцену still + клип «нырок» + коннекторы. Sora-2 надёжно пиннит старт-кадр (image-to-video); последний кадр не пиннится → стыки закрываем crossfade.
## 3. Сценарий пролёта (6 сцен, «путь в дом»)
1. **Лес / природа** — 25 км от Уфы, тишина, «атмосфера безопасности».
  
2. **Въезд в посёлок** — стела «Родная земля», ворота.
  
3. **Центральная аллея** — благоустройство, 25 га, 103 дома.
  
4. **Подлёт к дому** — типы Земля / Огонь / Воздух / Вода.
  
5. **Внутрь дома** — потолки до 4.7 м, панорамное остекление до 30%.
  
6. **Терраса и сад** — приватность, BBQ-зоны, фруктовый сад.
  

Между сценами — connector-клипы, стык маскируется crossfade.
## 4. Архитектура (3 слоя)
### 4.1 Asset pipeline (офлайн, разовый прогон)
- `lib/sora/` — обёртка над Azure AI Foundry: image-to-video для каждой сцены (клип «нырок») и коннекторов.
  
- Image-модель Azure — still-постеры сцен.
  
- `ffmpeg`/`ffprobe` — нарезка кадров, склейка коннекторов, кодирование в `webm` (основной) + `mp4` (fallback). Скрипты адаптированы из `scroll-world/references/pipeline.md`.
  
- Выход складывается в `public/scroll/`.
  
- Ассеты в git **не** коммитим (тяжёлые) — генерируются/деплоятся отдельно.
  
### 4.2 Scrub-engine (клиент)
- Порт `scrub-engine.js`: blob-seek видео по scroll-прогрессу, lazy-load сцен (IntersectionObserver), seam crossfade.
  
- Источник кадра абстрагирован: `video-scrub` по умолчанию, `image-sequence` на Safari / слабых устройствах / медленной сети.
  
- Обёрнут в клиентский компонент `components/ScrollWorld/`.
  
### 4.3 Next.js app (App Router, SSR)
```
app/
  page.tsx            — <Hero/> (ScrollWorld) + секции контента
  layout.tsx          — метаданные, шрифты, OpenGraph
components/
  ScrollWorld/        — движок + scenes.ts (конфиг сцен)
  Houses/             — каталог 4 домов, цены от 38 млн ₽
  Amenities/          — карта благоустройства (umap)
  WhyAul/             — табы характеристик (Дом/Территория/Спорт/…)
  Manifesto/          — философия/манифест
  Cta/, Footer/
lib/sora/             — Azure Foundry обёртка (для pipeline)
public/scroll/        — сгенерённые webm/mp4/кадры/постеры
```
### 4.4 Конфиг сцен
`components/ScrollWorld/scenes.ts` — массив 6 объектов:

```ts
{ id, title, subtitle, still, clip, connector, textOverlay }
```

Правка порядка/подписей = правка конфига. Валидируется zod-схемой: все пути ассетов существуют, цепочка коннекторов связная.
## 5. Fallback / доступность (критично: недвижимость + SEO)
- `prefers-reduced-motion` **или** нет WebGL / медленная сеть → статичный постер hero + якорные подписи сцен, обычный скролл.
  
- Mobile → облегчённый image-sequence (меньше кадров) либо постер.
  
- Весь текст сцен и секций рендерится в DOM (SSR), не «зашит» в видео → индексируется поисковиками. Видео — прогрессивная деградация поверх.
  
## 6. Производительность
- Бюджет hero: ≤ ~8-12 МБ на первый экран.
  
- Preload только первого клипа; остальные сцены — lazy по скроллу.
  
- Постеры — `<img>` с высоким приоритетом (LCP).
  
- Целевые метрики: LCP < 2.5 c, отсутствие layout shift на hero.
  
## 7. Тестирование
- **Unit:** чистая функция `scrollProgress → time/frame` (без браузера).
  
- **Конфиг:** zod-валидация `scenes.ts` (пути существуют, порядок связный).
  
- **E2E (Playwright):** скролл двигает hero; при reduced-motion рендерится постер-фолбэк; текст секций присутствует в SSR-разметке.
  
- **Спайк-гейт (обязателен до полной генерации):** 1 сцена + 1 коннектор на Sora-2 → проверка бесшовности, стиля, веса. Плохие стыки → переключение на image-sequence (B) без переписывания движка.
  
## 8. Вне объёма (YAGNI)
- WebGL/Three.js (подход C).
  
- CMS-интеграция, многоязычность.
  
- Кастомный видеоплеер — берём готовый scrub-engine.
  
## 9. Риски
| Риск | Митигация |
| --- | --- |
| Sora-2 не держит консистентный стиль/свет между сценами | Спайк на 1 сцене; единый промпт-темплейт; фикс сид/референс |
| Стыки не бесшовны | crossfade + при необходимости image-sequence |
| Вес ассетов бьёт по LCP | Бюджеты, lazy-load, webm, постер-first |
| Доступ/квоты Sora-2 в Azure Foundry | Проверить на спайке до планирования полной генерации |
